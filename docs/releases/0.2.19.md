AutoPierCam 0.2.19 adopts Regain 0.5.6 and extends experimental Direct USB video
to ASI676MC, following ASI662MC video in 0.2.18. SDK remains the default; existing
configurations do not change driver or enable USB recovery.

## Changes

- Use the worker's advertised video mode for ASI676MC exposures through 30 seconds
  on USB 2 and USB 3. Both supported color models now reuse sensor initialization
  and calibration between matching frames.
- Preserve model-specific ROI, gain, offset and timing limits. Longer exposures
  use retained still capture; there is no silent SDK fallback or reduced ceiling.
- Preserve fractional acquisition FPS caps, exposure-aware stall deadlines,
  cancellable waits, WB/AWB, cached identity and discovery backoff.
- Keep 30-second automatic capture retry and optional serial-bound USB recovery.

## Optional USB recovery

The Viewer can optionally reset the selected camera's port after capture failure.
This remains off by default and requires an explicit serial plus an
administrator-started agent. Identity checks and a five-minute cooldown remain;
no hub-wide reset, automatic elevation or local installed-setting changes.

## Validation and limits

Regain's operator-authorized ASI676MC SDK references and Direct USB matrices passed
on Windows USB 2 and USB 3. Each matrix covered 21 video frames, full frame/ROI,
fractional FPS, exposure changes through 30 seconds, cancellation, restart and
return to still capture. AutoPierCam adapter/pipeline regressions use simulations.

FPS caps grabs, not sensor output; slow consumers may receive buffered frames.
Optical accuracy, cold startup, physical USB-disconnect recovery, long-running
stability, Linux/macOS video hardware and the installed Viewer's full driver
handoff remain unvalidated. No private images or identities are bundled.

## Install or upgrade

Use **AutoPierCam-0.2.19-x64.msi**. Settings and images are preserved; the ZWO USB
driver remains required. Previously published assets are unchanged.

NINA plugin **0.2.19.0** must be published to both
`https://nina-plugins.psf-guard.com/` and `https://nina-plugins.pulsarfab.com/`.
Minimum NINA version remains **3.2.0.9001**. The plugin never owns the camera.
