AutoPierCam 0.2.27 adds Windows-native video, daily timelapses from saved stills,
and richer opt-in Chatstronomy sharing. Regain remains pinned to the released
0.5.15.1 source (Rust crates 0.5.15); camera acquisition is unchanged.

## Changes

- Replaces the external FFmpeg encoder with Windows Media Foundation H.264 MP4
  for security segments and daily timelapses. Hardware encoding is allowed with
  a Windows software fallback. No separate encoder installation is required;
  Windows N needs the Media Feature Pack. Old `ffmpeg_path` settings are ignored.
- Daily timelapses use the first saved still in each UTC minute. A closed UTC
  day is processed at startup or the next periodic check. Private sample caches
  are bounded and removed after successful local publication and registration;
  original stills remain subject to their ordinary retention policy. Local
  publication does not itself mean an upload or Discord post.
- Adds optional target, successfully saved LIGHT-exposure count, and focuser or
  external temperature labels. All toggles default off. An explicit telescope
  selection and fresh Hub v4 telemetry are required. Unknown or stale values
  are omitted; later telemetry never relabels an earlier captured sample.
  Overlays affect private timelapse samples, not the original stills.
- Adds richer target/action captions and separately consented daily-movie
  sharing. The existing v3 upload contract is unchanged. Hub-advertised limits
  are honored up to an independent 512 MiB client ceiling; higher limits do
  not invalidate the connection. A private disk snapshot streams in bounded
  chunks with Content-Length, preserving identical bytes, UUID and timestamp
  across bounded retries. Quota admission and rechecks include the extra copy.
- Size/media rejection is terminal and visible. Discord may reject larger
  clips even when the Hub accepts them; the local movie is not modified by
  sharing and remains available subject to normal retention. MP4s are never
  split into arbitrary attachments. Consent withdrawal and cancellation clean
  up the private upload snapshot.
- Fixes replayed older telemetry reviving labels after a newer clearing state.
  Existing motion images and conservative estimated post-slew freshness remain
  intact; no exposure is cancelled or restarted for sharing.

Overlays require the Hub v4 observation-state support shipped in Chatstronomy
0.4.13 and source telemetry from NINA plugin 0.1.0.34 or compatible newer
versions, deployed together. Legacy peers retain their negotiated capabilities.
See [video setup](../video.md) and [sharing setup](../chatstronomy.md) for size,
retention, consent and timing details.

## Validation scope

Validation uses synthetic frames, loopback HTTP/WebSocket peers, simulated
camera workers and software tests. Regressions cover uploads above 20 MiB,
bounded chunks, immutable retries, rejection, cancellation, quota cleanup,
telemetry freshness and replay. No physical-camera, optical, long-soak or local
installed-artifact validation is claimed. Host capture times are not guaranteed
sensor exposure timestamps; missing telemetry is not interpolated.

## Install or upgrade

Use **AutoPierCam-0.2.27-x64.msi** to update the agent and Viewer together.
Existing settings and images are preserved; video, movie sharing and overlays
are opt-in. NINA plugin **0.2.27.0** is distributed through both public feeds,
`https://nina-plugins.psf-guard.com/` and `https://nina-plugins.pulsarfab.com/`.
Minimum NINA remains **3.2.0.9001**. The plugin never opens a camera handle.
