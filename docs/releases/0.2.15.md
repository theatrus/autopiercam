AutoPierCam 0.2.15 improves camera selection and unattended recovery, supports
fractional preview frame rates, and removes repetitive status logging.

## Changes

- Show discovered camera serials and per-device discovery failures in Viewer.
  Choosing a camera fills its serial; matching ignores hexadecimal letter case,
  and blank serial input remains optional for a single matching camera. Identical
  models require explicit selection; Direct USB product IDs are not unique serials.
  Regain now preserves USB open/probe failures without incorrectly describing
  every such failure as a missing serial. This does not claim the reported
  physical ASI662MC failure was reproduced or resolved on hardware.
- Add opt-in Windows USB port recovery after fatal capture/exposure faults.
  Recovery requires an explicit nonzero serial and a persistently elevated agent.
  The old worker is closed first; the helper checks the bound device generation
  and cycles only its parent-hub port. Attempts are limited to one per five
  minutes. No whole-hub resets, UAC prompts or automatic driver switching occur.
  Normal capture retries remain 30 seconds after cleanup. Port cycling is not a
  guarantee of physical power removal or recovery. No service/task is installed.
- Allow preview rates from 0.01 through 30 fps, including 0.5 and 0.1 fps.
  Intentional pacing no longer consumes the frame deadline. Still schedules can
  request frames sooner; startup settling retains a 1 fps acquisition floor.
- Log capture status only when state, selected camera or error changes. Elapsed
  exposure time and frame counters still update the Viewer without log spam.

USB recovery is disabled by default; run the tray agent as administrator under
the same Windows user to enable it. Launch Viewer normally if it should remain
unelevated; launching it from an elevated tray inherits elevation. Installed
configuration is not automatically changed. SDK remains the default backend.

Validation uses synthetic cameras and data, not physical cameras. ASI662MC
Direct USB remains experimental: prior upstream Windows evidence covers through
600 seconds, not the advertised 2,000-second maximum. Cold startup, optical
accuracy, physical reset recovery and Linux/macOS hardware remain unvalidated.

## Install or upgrade

Install **AutoPierCam-0.2.15-x64.msi** to update the agent and Viewer. Existing
settings, pairing and images are preserved. The ZWO Windows USB driver remains
required. Save an explicit camera serial before enabling USB recovery.

NINA plugin **0.2.15.0** is published to both shared registries:

- `https://nina-plugins.psf-guard.com/`
- `https://nina-plugins.pulsarfab.com/`

Minimum NINA version remains **3.2.0.9001**. The plugin requires the separately
installed agent and never owns the camera.
