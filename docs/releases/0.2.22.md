AutoPierCam 0.2.22 improves preview timing with Regain 0.5.9. SDK remains
the default. Camera selection and existing configuration are preserved.

## Changes

- Keep preview flowing during exposure/gain transitions. Frames whose settings
  are not settled have unknown exposure/gain metadata; they cannot drive
  auto-exposure, satisfy startup convergence, or consume saved snapshot requests.
- Serve cached stream status and latest frames independently of blocking SDK
  reads. Use atomic frame polling and retain bounded latest-only buffering.
- Increase the SDK video-read cap from 1s to 5s and give owner commands enough
  IPC time to finish a read. The exposure-aware watchdog and terminal errors
  remain enforced; this is not an unbounded timeout or retry loop.
- Add raw-frame timing diagnostics so acquisition and delivery can be distinguished.
  Preserve the delivery FPS cap, single camera owner and boundary-safe controls.

Automated tests use simulators and inert SDK libraries, including a deliberately
blocked acquisition read and blocked output. No automated test opens hardware.
The reported SDK stall's underlying cause is not proven. These changes do not
claim a firmware/power fix, optical settings accuracy or long-soak validation.
No images, camera identities or raw traces are included in the release.

## Install or upgrade

Use **AutoPierCam-0.2.22-x64.msi**. Existing settings and images are preserved;
the ZWO USB driver remains required. Previous releases are not overwritten.
NINA plugin **0.2.22.0** is published to both public plugin feeds:
`https://nina-plugins.psf-guard.com/` and `https://nina-plugins.pulsarfab.com/`.
Minimum NINA remains **3.2.0.9001**; the plugin never opens a camera handle.
