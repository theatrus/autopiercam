AutoPierCam 0.2.23 fixes Direct USB startup selection and updates the bundled
worker to the released Regain 0.5.10 drivers. SDK remains the default.

## Changes

- When a stale saved camera ID rejects all Direct candidates, use the saved
  model filter to select one unambiguous interface whose serial is not yet known.
  Open only that interface on the capture thread and verify the saved serial
  before capture. A serial mismatch still fails; multiple matching interfaces
  still require explicit selection. Saved configuration is not rewritten.
- Keep discovery metadata-only. The Viewer can show "serial unavailable" until
  the selected camera is opened; discovery does not probe other cameras.
- Pin Regain 0.5.10.0's released source and update the worker packaging contract
  and dependency notices. Upstream adds experimental ASI585MM Pro support, but
  AutoPierCam still requires a color camera and does not enable monochrome capture.

Hardware-free regressions cover the stale-ID startup failure, ambiguity, missing
interface identity, known serial mismatches, cached verified identity, and actual
worker acceptance/rejection of a saved serial. The startup regression fails
against the old selection behavior. This release adds no new physical-camera,
optical, disconnect, or long-soak validation.

## Install or upgrade

Use **AutoPierCam-0.2.23-x64.msi**. Existing settings and images are preserved;
the ZWO USB driver remains required. Previous releases are not overwritten.
NINA plugin **0.2.23.0** is published to both public plugin feeds:
`https://nina-plugins.psf-guard.com/` and `https://nina-plugins.pulsarfab.com/`.
Minimum NINA remains **3.2.0.9001**; the plugin never opens a camera handle.
