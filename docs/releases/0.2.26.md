AutoPierCam 0.2.26 updates the bundled Regain camera worker from 0.5.11 to
the released 0.5.14.0 source. The pop-out settings window, shared Imaging and
Chatstronomy saves, clock-aligned periodic sharing and post-slew image selection
from earlier releases are retained.

## Changes

- Pins all Regain dependencies to the same released commit,
  `e9b7c46751c26035c2a7853aa5f75e6e9b09ed06`. The four Rust crates use version
  0.5.14; the worker version label and packaging check match that version.
- Includes the intervening upstream maintenance changes to recovery diagnostics
  and Direct cooling regulation. AutoPierCam's low-level adapter does not use
  Regain's shared camera-session supervisor or its NINA/ASCOM frontends, so their
  cooling-restoration, chart and Driver Info changes are not new AutoPierCam UI
  features. AutoPierCam still requires a color camera.
- Keeps camera selection, exposure handling, continuous-frame delivery and
  automatic recovery policy unchanged. No exposure is cancelled to obtain a
  post-slew image; timing remains an explicitly conservative estimate.

## Validation scope

The dependency integration uses hardware-free SDK and Direct worker simulation,
including frame provenance, transitions, serial selection, error cleanup and
the preview pipeline. Physical-camera, optical timing and long-soak validation
are not part of this update. Published upstream hardware results do not qualify
AutoPierCam on every camera model.

## Install or upgrade

Use **AutoPierCam-0.2.26-x64.msi** to update the agent and Viewer together.
Existing settings and images are preserved. NINA plugin **0.2.26.0** is
distributed through both public plugin feeds:
`https://nina-plugins.psf-guard.com/` and `https://nina-plugins.pulsarfab.com/`.
Minimum NINA remains **3.2.0.9001**. The plugin never opens a camera handle.
