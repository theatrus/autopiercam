AutoPierCam 0.2.2 fixes saving settings with disabled retention limits and makes
the camera-selection workflow easier to use.

- Fixes `invalid_config: missing required field config.capture.retention_max_bytes`
  when saving a camera selection or other settings with unlimited retention.
  Disabled limits are explicitly sent as null; older agents that lack the fields
  retain their original wire format.
- Keeps the camera picker, save button and save/error feedback visible outside
  the scrolling settings area. Activity cards are collapsed by default.
- Shows **Settings loaded**, **Unsaved changes**, and **Settings saved** instead
  of displaying an internal configuration fingerprint as a version number.
- Labels the action **Save and restart capture**. Save is enabled after an edit.
- Refresh asks before discarding pending edits; Capture now preserves them.
- A rejected configuration no longer disables unrelated agent capabilities.
- Adds shared Rust/C# configuration-contract tests, actual named-pipe save-request
  tests, legacy/disabled retention tests, and pinned-layout regression checks.

Install the signed **AutoPierCam-0.2.2-x64.msi**. Existing settings are retained.
Select the camera, then use the always-visible **Save and restart capture** button.
The MSI and application payloads are signed as **StackFoundry LLC**.

The NINA plugin **0.2.2.0** is also published through the shared theatr.us registry
at `https://nina-plugins.psf-guard.com/` and `https://nina-plugins.pulsarfab.com/`.
It still requires the separately installed capture agent and NINA 3.2.0.9001+.
