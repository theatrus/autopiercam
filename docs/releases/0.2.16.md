AutoPierCam 0.2.16 reduces camera discovery during startup and unattended recovery.
This corrects the automatic all-camera serial probing introduced in 0.2.15.

## Changes

- Cache inventory and the selected camera's verified identity across capture
  worker replacement. A 30-second capture retry no longer triggers discovery.
- Remove automatic all-camera serial probing. Learn and display the serial from
  the selected camera after connection, without opening other cameras for it.
- Reopen SDK cameras by the selected ID and verify the expected serial before
  initialization. Do not repeat the all-camera property scan. Direct USB opens
  only the cached interface and verifies its serial; a missing, busy or changed
  target never triggers a fallback sweep.
- Back off failed or empty discovery independently: 5, 10, 20, then 30 minutes.
  Successful inventory stays cached. Viewer camera-list refresh remains cache-only.
- Restrict USB recovery binding to one selected interface; refuse ambiguous
  same-model devices rather than probing every serial. Existing explicit opt-in,
  administrator requirement, generation checks and five-minute reset cooldown remain.

For changed hardware, deliberately restart the agent when other camera owners
are idle. A changed SDK ID or USB interface after a reset can require operator
rediscovery. Identical Direct USB models with unknown serials remain ambiguous
and are not silently selected. SDK remains the default; installed settings are
not modified automatically.

Initial SDK descriptor discovery is still an active operation, and the vendor
SDK may enumerate USB internally. This patch is not a system-wide ownership lock
or a guarantee of recovery from an existing USB-stack deadlock. Tests use synthetic
ABI call counts and simulators, not physical cameras. ASI662MC Direct USB remains
experimental; prior upstream Windows evidence covers through 600 seconds, not
the advertised 2,000-second maximum. Mixed-application hardware safety, cold
startup, optical accuracy and physical reset recovery remain unvalidated.

## Install or upgrade

Install **AutoPierCam-0.2.16-x64.msi** to update the agent and Viewer. Existing
settings, pairing and images are preserved. The ZWO Windows USB driver remains
required. Published 0.2.15 assets are unchanged.

NINA plugin **0.2.16.0** is published to both shared registries:

- `https://nina-plugins.psf-guard.com/`
- `https://nina-plugins.pulsarfab.com/`

Minimum NINA version remains **3.2.0.9001**. The plugin never owns the camera.
