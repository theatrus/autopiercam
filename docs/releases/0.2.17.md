AutoPierCam 0.2.17 adopts Regain 0.5.4 for USB 2 Direct USB capture fixes.
This update is recommended for ASI662MC/ASI676MC users whose USB 2 connection
was rejected when switching from SDK to Direct USB. SDK remains the default;
existing configurations do not switch drivers or enable USB recovery.

## Changes

- Pin the bundled worker and Rust camera drivers to Regain's 0.5.4.0 release.
  Validated USB 2 high-speed layouts are accepted alongside USB 3; ambiguous or
  unsupported descriptors still fail closed.
- Preserve integration time while pacing very short ASI662MC/ASI676MC USB 2
  frames, fixing the observed ASI676 retained-replay mismatch.
- Include upstream Duo complete-readout and tiny-ROI fixes. These do not expand
  AutoPierCam's supported color-camera scope to monochrome deep-sky cameras.
- Retain cached-identity reconnects, 30-second automatic capture retries,
  independent discovery backoff, manual/AWB controls and fractional preview FPS.

## Optional USB port reset

Viewer Settings includes **Reset this camera's USB port after capture failure**.
It is **off by default**. To opt in, save the selected camera's explicit serial
and run the AutoPierCam tray agent persistently as administrator under the same
Windows account. The setting is also available as `camera.usb_reset_on_fault`.

After a fatal capture/transfer failure or exposure deadline, the camera worker
is closed before Regain attempts recovery of the verified camera's immediate
port. Identity and device generation must still match. There is at most one
attempt per failed session and a five-minute cooldown, including failed resets.
The helper never resets an entire hub, guesses another camera, or prompts for
elevation. Missing identity, changed interfaces or insufficient privileges fail
closed; ordinary retry remains available. Reset does not guarantee power removal
or recovery from a wedged USB controller. No local installation, settings change
or physical reset was performed for this release.

## Validation and limits

Upstream Windows USB 2 evidence covers ASI662MC/ASI676MC full frames, 30-second
exposures, exact retained replay and interrupted reads. Separate upstream 2600
P25/Duo matrices passed, including a Duo USB 3 regression. ASI6200 extreme-gain
uniformity remains qualified and is not presented as a clean matrix pass.
See the [Regain backend guide](https://github.com/theatrus/autopiercam/blob/v0.2.17/docs/regain-backend.md).

AutoPierCam's automated checks use simulators, not physical cameras. Physical
port-reset/reconnect and mixed-camera isolation, cold startup, optical accuracy,
Linux/macOS hardware and a complete installed-Viewer SDK-to-Direct handoff remain
unvalidated. ASI662MC's advertised 2,000-second maximum is not hardware-validated.

## Install or upgrade

Install **AutoPierCam-0.2.17-x64.msi** to update the agent and Viewer. Existing
settings, pairing and images are preserved. The ZWO Windows USB driver remains
required. Published 0.2.16 assets are unchanged.

NINA plugin **0.2.17.0** is published to both shared registries:

- `https://nina-plugins.psf-guard.com/`
- `https://nina-plugins.pulsarfab.com/`

Minimum NINA version remains **3.2.0.9001**. The plugin never owns the camera.
