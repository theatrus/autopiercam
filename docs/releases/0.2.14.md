AutoPierCam 0.2.14 fixes capture remaining stopped after a camera fault and adds
startup lighting selection and shared white-balance controls.

## Changes

- Automatically retry failed camera sessions after 30 seconds. The previous
  fault latch prevented scheduled retries. The supervisor waits for the old
  camera owner to exit before opening the selected camera again; it never
  opens overlapping handles. Recording pause and queued capture requests are
  preserved. Restart or a settings save can retry sooner; quitting cancels retry.
- Choose the initial adaptive day/night mode from UTC time and configured
  latitude/longitude. Night begins below a solar altitude of -6 degrees.
  Measured brightness still controls subsequent transitions; missing location
  retains the existing startup behavior.
- Update to Regain 0.5.3, pinned to its v0.5.3.0 release, and expose Disabled,
  Manual, Auto once and Continuous AWB in Viewer Settings for SDK and Direct USB.
  Regain owns the shared estimator and Bayer correction; AutoPierCam does not
  apply another white-balance pass.
- Correct driver version reporting and document mixed SDK/Direct USB diagnostics.

This update is recommended for unattended capture. Retrying a session does not
guarantee recovery from a disconnected or stuck camera, and does not diagnose
the underlying SDK exposure failure. No USB reset, automatic backend fallback,
or concurrent camera discovery is added.

White balance remains disabled by default. Manual red/blue gains are linear
multipliers relative to green, not ZWO SDK slider values. Enabled white balance
also affects 16-bit PNGs; these are no longer unmodified sensor data. Gray-world
AWB can be unsuitable for sparse night skies or strongly colored scenes.
Managed SDK white balance is restored on orderly close, but restoration cannot
be guaranteed after a crash or forced worker termination.

ASI662MC Direct USB remains experimental. Upstream Windows evidence covers
exposures through 600 seconds; the advertised 2,000-second maximum is not
hardware-validated on this model. Cold startup, optical accuracy, physical
white-balance calibration and Linux/macOS hardware remain unvalidated.
Release tests use simulators, not physical cameras.

## Install or upgrade

Install **AutoPierCam-0.2.14-x64.msi** to update the agent and Viewer. Existing
settings, pairing and saved images are preserved. SDK remains the default and
existing configurations do not switch drivers. The ZWO Windows USB driver is
still required. Configure location and white balance explicitly in Settings
when wanted; the release does not supply site coordinates or change WB defaults.

NINA plugin **0.2.14.0** is published through both shared registries:

- `https://nina-plugins.psf-guard.com/`
- `https://nina-plugins.pulsarfab.com/`

Minimum NINA version remains **3.2.0.9001**. The plugin requires the separately
installed AutoPierCam agent and never owns the camera.
