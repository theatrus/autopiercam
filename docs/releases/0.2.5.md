AutoPierCam 0.2.5 fixes Chatstronomy settings validation and scene-change
reporting, and gives more space to the live preview.

- Fixed the false changed-area percentage error when editing the send interval
  with scene settings collapsed. Save validates the current numeric text;
  reopening or discarding the dialog is no longer needed.
- Scene detection compares against the last scene-change image acknowledged as
  delivered by the Hub (or the initial reference until the first report). Slow
  drift accumulates; exposure changes and dark interruptions do not silently
  replace the reference. Retries retain the exact sent image, and the reference
  survives network reconnects. Capture-session and permission changes reset it.
- Unknown lighting mode no longer blocks scene detection. SDK auto mode now
  reports Day/Night from completed exposure times, with separated thresholds
  and a three-frame, 30-second transition window. This describes camera lighting
  conditions, not an astronomical sunrise/sunset calculation.
- Replaced large telemetry cards with a compact exposure/gain/mode summary and
  removed the protocol/pipe footer. Missing readings are hidden.
- Renamed **Capture now** to **Save next frame** in the Viewer and tray. It saves
  an extra full-resolution still after an exposure completes; it does not force
  a new exposure or send directly to chat. **Reload settings** is now inside
  Settings; the preview and status already update automatically.

Install the signed **AutoPierCam-0.2.5-x64.msi** to update the agent and Viewer.
Configuration, captures and pairing credentials are retained. Upgrading does
not enable image sharing. The MSI and application payloads are signed as
**StackFoundry LLC**. ZWO camera drivers and optional FFmpeg remain separate.

The signed NINA plugin **0.2.5.0** is published to the shared registry at
`https://nina-plugins.psf-guard.com/` and `https://nina-plugins.pulsarfab.com/`.
It requires NINA **3.2.0.9001+** and the separately installed AutoPierCam agent
on the same PC and Windows account.

Telescope-trigger routing is unchanged: the Hub matches telescope and camera
by owner and shared chat destination, not an explicit camera-to-scope binding.
Scene detection is not person/roof classification or a security alarm.
