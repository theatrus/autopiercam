AutoPierCam 0.2.0 adds opt-in Chatstronomy image sharing and triggered sends to
the Windows tray agent and Viewer.

## Downloads

- **AutoPierCam-0.2.0-x64.msi**: signed per-user Windows x64 installer for the
  capture agent and Viewer. Run it to upgrade 0.1.0; settings, captures, logs and
  upload history are retained. Install the ZWO camera driver separately.
- **AutoPierCam.NINA.0.2.0.0.zip**: signed read-only Imaging-tab plugin for N.I.N.A.
  3.2 or newer. Close N.I.N.A. before extracting into
  `%LOCALAPPDATA%\NINA\Plugins\3.0.0\AutoPierCam`.
- The plugin manifest and **SHA256SUMS.txt** accompany these downloads.

First-party Windows binaries, the plugin DLL and MSI are Authenticode signed as
**StackFoundry LLC**. Author: Yann Ramin. License: Apache-2.0.

## New in this release

- Pair a pier camera from the Viewer's **Chatstronomy** dialog. Credentials are
  protected by Windows Credential Manager and bound to the Hub and installation.
- Independently enable requested snapshots, persistent scene changes, stable
  day/night transitions, periodic images, or telescope-event image bursts.
- Periodic sends use a distinct recent frame every 1–1440 minutes. Events can
  send 1–3 updated images, spaced 60–600 seconds apart, without interrupting
  long exposures or opening another camera handle.
- Optionally allow owner-only `/piercam triggers` configuration from chat.
  Chat cannot enable locally disabled sources, increase burst sizes, shorten
  locally selected intervals, or enable sharing. Local Save permissions resets
  chat overrides; the Viewer displays active rules.
- `/piercam snapshot` requests the latest completed image using its separate
  local permission. Slew start/end and sequence start/finish can trigger images
  only for cameras with the same owner and a shared Hub channel route.
- Bounded image sizes, retries, freshness checks, burst expiry and cancellation
  keep network sharing separate from capture. Nothing is shared by pairing alone.

## Setup and limitations

Create a camera and select its destination channels in the Hub, then pair and
enable only the permissions you want in the Viewer. Advanced triggers/chat
commands require the Hub update in
[Chatstronomy #186](https://github.com/theatrus/chatstronomy/pull/186).
Merging that change does not deploy it; update your Hub before enabling v2 features.

Images contain the entire preview and go to all configured camera destinations.
There are no privacy masks or person/roof classifiers. Scene changes are generic
observations, not security alarms. Bursts have no pre-event buffer and keep a
device-wide 60-second cooldown; long exposures or delivery failures may delay or
reduce the images. Stop sharing cancels queued work but cannot recall posted
messages. Retries can occasionally duplicate a message after a Hub crash.

Capture, exposure, HTTP uploads and optional FFmpeg recording remain available
without Chatstronomy. FFmpeg is not bundled. Production credentials are currently
Windows-only; portable components are tested with synthetic images. No physical
camera or live Discord delivery was used to validate this release's sharing code.

See the [sharing guide](https://github.com/theatrus/autopiercam/blob/v0.2.0/docs/chatstronomy.md)
and [installation guide](https://github.com/theatrus/autopiercam/blob/v0.2.0/docs/installation.md).
